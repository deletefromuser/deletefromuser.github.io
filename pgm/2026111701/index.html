Collections.singletonList 使用注意事项

2026-11-17 00:00
Tags:
  • Collections
  • java

报错现象

在对 Collections.singletonList() 返回的列表进行元素删除或保留操作时，抛出：

java.lang.UnsupportedOperationException: null
at java.base/java.util.Collections$1.remove (Collections.java:4821)
at java.base/java.util.AbstractCollection.retainAll (AbstractCollection.java:404)

原因

Collections.singletonList() 返回的是一个固定大小、不可修改的只读列表（内部类 Collections$1）。它不支持结构性修改操作，如 remove、retainAll、add、clear 等，调用这些方法会直接抛出 UnsupportedOperationException。

AbstractCollection.retainAll 内部会遍历并尝试移除不匹配的元素，进而触发 remove，因此报错。

避坑提示（IDEA 优化建议）

IDEA 在检测到代码将单个元素包装成列表时，可能会提示使用 Collections.singletonList() 进行优化。但如果该列表后续还需要做变更处理（增删改），且测试不完善，就很容易掉进这个坑里。

建议：

  1. 看到 IDEA 的优化提示时，先确认该列表后续是否需要结构性修改。
  2. 如果需要修改，不要盲目应用优化，或者在优化后立即包装成可变列表。
  3. 补充单元测试，覆盖列表的修改路径，避免线上运行时才暴露问题。

解决方案

在需要修改列表前，先将其包装成可变列表：

List<String> list = new ArrayList<>(Collections.singletonList("a"));
list.remove("a"); // 正常

或直接使用可变列表实现，避免对 singletonList 返回结果做增删操作。
